# ローカル実測

2026年11月25日、Windows 11 x64、Ryzen 7 5700U（8コア・16論理プロセッサ）、物理メモリ31.35 GiB、SDK 10.0.404、.NET 10.0.15で測定しました。BenchmarkDotNet 0.15.8、Release、デバッガーなし、エンジン間は逐次実行です。

主試料は日本語5行の不可視テキスト、埋め込みフォント、QRを含む600×360 JPEGを重ねた1ページ、33,580 Bです。実測時のファイルSHA-256は `1B94467F64EB8C74A9AF42463DF7E3C965A08376C1D4352F4544177CF1DFE8C7` です。読み取り順はコンテンツ順。単一ワーカーを使いました。24個のメソッドと条件の組合せが完走しました（主試料10＋ファイル2＋初回2＋別試料10）。

## 数値の読み方

- 時間はBDNが反復内の実行回数で割った1操作あたりの値。Allocatedはマネージ割り当ての1操作あたり、Gen列は1,000操作あたりのGC回数です。各レポートに生成された列だけを掲載しています。ErrorはBDNの信頼区間半幅です。
- 主試料の文書再利用時はOnePDFの合計平均108.87 µs、PdfPigの合計平均254.86 µsでした。ファイルからの開き直しでは平均460.4 µsと866.3 µsでした。字形矩形、単語分割、レイアウト解析、画像列挙の作業内容には差があります。
- BDNは一部の短い反復についてMinIterationTime、分布についてMultimodalDistributionを報告しました。ノートPC1台・合成票面での傾向です。CPUの電源状態、JIT、OSのキャッシュとスケジューリングの影響が残ります。
- WPFの簡易測定は開く処理、テキスト、座標、画像、合計を独立に反復します。段階別の文書準備・破棄は区間外。Openは開く処理とページ数、Total/Reopenは開く処理を含みます。Reuse時は段階ごとに文書を用意します。割り当ては単一ワーカーでは現在スレッド、複数ワーカーではプロセス全体です。GCはプロセス全体なのでWPF等の活動も影響します。失敗は分母から除き失敗件数を別に記録し、P95はnearest-rank、標準偏差は標本標準偏差です。
- 比較画面は段階の順序を固定し、各段階のStopwatch区間だけを合算します。表示、差分、進捗通知、ファイル保存は計測外です。メモリの明示キャッシュを共有するのは入力バイト列だけです。ライブラリ内部で保持するキャッシュはそのまま使います。並列ワーカーは同じドキュメントオブジェクトに同時アクセスしません。
- WPFでウォームアップを外した場合は同一プロセス内の初回を含みます。プロセス単位のコールド条件は専用プロジェクトの `--cold` を使います。BDNで個別段階に `--reopen` を指定した場合は各操作の開閉も含むため、ここでの文書再利用値と測定範囲が変わります。
