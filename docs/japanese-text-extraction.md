# 日本語の抽出結果

合成試料の既知の正解と、各エンジンのコンテンツ順出力を、UTF-16文字列の完全一致で照合しました。ページ境界だけは共通のFFで接続します。全14種類のうち2種類はエラーを期待する異常系です。両エンジンが一致しても正解とは限らないため、各PDFには独立した期待テキストを付けています。[試料別の結果](../fixtures/observations.md)

| 試料 | 観察 |
|---|---|
| 日本語横書き | 両方とも「処方箋 ひらがな カタカナ ＡＢＣ ｶﾅ 髙」に完全一致。埋め込みType 0フォントとToUnicodeを使用 |
| 縦書き | Identity-Vの「縦書き見本」に両方が一致。Popplerで縦方向の配置も目視確認 |
| 稀少文字マップ | 単純フォントの可視グリフABCに「𠮷」「葛＋U+E0100」「U+E001」をマップ。OnePDFが全スカラーを保持し、PdfPigはABCを返した。このフォント構成の結果であり、PdfPigのIVS一般の非対応を意味しない |
| 架空処方箋 | 正解の「架空処方箋　検証用見本」にPdfPigが一致。OnePDFではU+3000がU+0020になった。互換文字折りたたみを無効にしても、プレーンテキスト組み立て時の空白差が残る |
| 表 | 正解はセル間に空白、行間にLF。OnePDFが一致。PdfPigのPage.TextはItemCountDemo2を連結 |
| 日本語の透明テキスト＋JPEG | 両方が日本語OCR層とTr=3を取得。OnePDFは5行を保持し、全角空白1個が半角に変化。PdfPigは全角空白を保持し、行境界のLF4個を挿入しなかった。両方ともJPEGが生成時の元データとバイト単位で一致 |
| 画像のみ／透明層付き | 同じ構成のFlateスキャンで、画像のみは本文が空。透明層付きはDEMO RXに両方が一致。どちらも画像1配置を取得 |

原文に対するNFKC、トリミング、全半角変換は行いません。OnePDFではDecomposeLigatures、FoldCompatibilityForms、CollapseDuplicatesを無効にしています。アプリのNFCや空白無視を選択しても原文タブと保存対象の原文は保持します。

## 暫定採用判断

.NET 10の薬局PoCではOnePDFを最初の候補とします。日本語スキャン試料で透明層の識別、行構造、QRを含むJPEGの回収が同時にでき、今回の特殊CMapも保持しました。両者とも今回の破損・パスワード付きの異常系は例外として報告されました。ライセンスはどちらも許諾型で、採用範囲の画像処理に追加パッケージは不要でした。PdfPigには全角空白を保持できた利点があり、異なる解析結果を返す照合エンジンとして残す意味があります。

これは小規模な合成試料に基づく判断です。実機ScanSnapのOCR精度、複雑な縦組み・複数段組、外字フォントの多様性、長時間運転のメモリ傾向、版更新後の互換性は未検証です。次段階では実機で匿名の架空票面をスキャンし、機種・設定ごとに文字列、文字座標、JPEGまたは他の圧縮方式、原画像の照合を行います。処方箋項目の抽出やQR読取りを実装する前に、特に全角空白と異体字を業務上どう照合するかを決める必要があります。
